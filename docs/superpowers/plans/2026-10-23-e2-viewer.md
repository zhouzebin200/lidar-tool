# E2 Viewer Implementation Plan

Goal: E2 packets produce point frames in the existing web viewer, without ROS.
Architecture: isolate E2 protocol in native/plugins/robosense_e2.hpp and route inside the existing RoboSense ABI plugin; preserve other SDK paths.
Tech Stack: Python 3.10+, C++17, existing WebGL/ABI v2.
Spec: ../specs/2026-10-23-e2-viewer-design.md

- [x] Add failing detection and native protocol tests: arbitrary ports, 844/1296 byte packets, calibrated coordinates, dual returns, malformed data, frame boundaries.
- [x] Vendor default direction data and CRC with provenance; implement E2 frame assembler/calibration in a separate header.
- [x] Route E2 in robosense_adapter.cpp, add Python detection without changing other models.
- [x] Build native plugin, verify ABI output through NativePluginManager, run Python regression and native ASAN/UBSAN.
- [x] Document setup/known validation limits; publish only changed files on the verified main baseline.

Review focus: calibration must not lose existing table on corrupt/incomplete transfer; no unbounded frame growth; no invalid zero vectors; duplicate/out-of-order packets must not multiply points; existing SDK models retain decoding and probing.
