# 项目结构与维护

当前默认交付为无授权 Windows x64 单文件版，构建入口 `packaging/build_unlicensed.py`，输出 `dist/unlicensed-x64/Lijian-LidarTool-Windows-x64.exe`，内置 Npcap 离线安装向导。授权版入口 `run_licensed.py` 和构建脚本 `packaging/build_report.py` 仍保留，按需构建。历史发布产物已按要求删除。

源码开发入口 `run.py` 不检查授权。点云和报告共用本地 HTTP 服务，默认 `http://127.0.0.1:17777`。升级前先退出旧进程，避免新 EXE 只打开旧进程的页面。
## 主要目录

| 路径 | 用途 |
| --- | --- |
| `ulv/` | 服务入口、二层抓包、设备识别、PTC/网页读取、网络临时配置与恢复、PCAP 回放和原生插件管理。 |
| `web/` | 点云查看器、网关页面、报告编辑器、三视图桥接和 PDF/PNG 导出。 |
| `native/` | C ABI 与各厂家解码适配器源码。 |
| `plugins/` | 本机编译的原生解码 DLL；随授权发行目录提供。 |
| `corrections/` | 解码所需的标称修正文件；逐台工厂修正优先。 |
| `tests/` | Python 回归测试；`manual/report_integration_harness.py` 用于报告集成检查。 |
| `packaging/` | Windows 融合版、历史授权版和 OpenWrt 网关的独立构建入口。 |
| `scripts/` | SDK 获取、原生插件编译与 PCAP 验证工具。 |
| `openwrt/` | 可选网关包，与 Windows 查看器分开部署。 |
| `build/`、`dist/` | 中间产物与当前发布文件；不再保存过时发布包。 |

`vendor/` 保存官方离线安装器等二进制依赖；`third_party/` 为 SDK 源码或依赖，`config/` 为本机运行配置，`tmp/` 为开发调试文件。不要把 `licensing/private/`、许可证私钥、`config/` 中的本机状态或整个项目目录发给最终用户。

## 数据进入报告的路径

1. `ulv/capture.py` 接收在线 UDP/PCAP 数据，`ulv/detection.py` 识别型号，`ulv/native_plugins.py` 调用厂家解码插件。
2. `ulv/registry.py` 保存当前设备；查看器的 `/api/devices` 和 `/api/status` 提供 IP、点云及插件状态。
3. 报告在 `web/report-viewer-link.js` 选择在线设备，再由 `web/report.js` 调用 `/api/lidar-web?ip=...`。
4. `ulv/lidar_web_scraper.py` 优先读取设备 HTTP/CGI 网页；网页不可达时才尝试兼容型号的 PTC。Pandar40P 的网页 `device_info`、`lidar_config`、`ethernet_all`、`TimeStatistic` 可提供型号、SN、生产日期、版本、转速、网络和运行统计。`ulv/hesai_ptc.py` 的 AT128 布局不得用于 Pandar40 系列的报告字段。
5. `web/viewer-report-bridge.js` 与 `web/report-viewer-link.js` 从当前点云帧生成斜视及两个侧视；`web/report-export.js` 负责报告 PDF/PNG 输出。

网页或 PTC 没有返回的电压、电流等值保持空白。软件队列丢包统计不能当作单台雷达的网络丢包率，点云帧率也不能当作机械转速。

## 开发、验证和发布

```powershell
./start.ps1
python -m unittest discover -s tests
python packaging/build_unlicensed.py
```

授权版仍可通过 `python packaging/build_report.py` 构建。该流程需要 `nuitka==4.3` 和 `cryptography`，使用 Nuitka 支持的 MinGW64 工具链将后端编译为原生 EXE，并随目录提供 `web/`、`corrections/` 和现有 `plugins/*.dll`。授权版构建后输出 `dist/customer/Lijian-LidarTool-Licensed.zip`，须整包解压；原有旧包已删除。构建自动审计目录及 ZIP 内容，不带本机配置、许可证或私钥；发布前仍应确认 DLL 与雷达兼容。`packaging/legacy/build_portable.py` 是历史流程，会生成普通版、授权版和含私钥的发码工具，不作为当前客户发行入口。

更新后先正常退出旧程序，确保端口 17777 已释放，再启动新 EXE。进入报告读取同一台在线雷达，核对型号、SN、转速和运行时间，然后抽查 PDF/PNG。若 `/api/lidar-web` 返回 404，说明实际运行的仍是缺少该接口的旧程序。

## 文件放置约定

- 业务代码：Python 放 `ulv/`，网页放 `web/`，原生适配器放 `native/plugins/`。现有资源路径不变。
- 自动测试：Python 放 `tests/test_*.py`，浏览器检查放 `tests/browser/`，人工演示工具放 `tests/manual/`。
- 构建：正式构建和审计放 `packaging/`，历史工具放 `packaging/legacy/`，SDK/编译辅助放 `scripts/`。
- 文档：完整使用指南放 `docs/guides/`，设计方案放 `docs/design/`，历史资料放 `docs/history/`，验收证据按日期保存。
- 本地状态：不要把 `config/runtime.json`、网络恢复日志、设备工厂标定缓存或私钥当作静态资源提交。`config/varID/` 是静态型号资料，与本机运行状态分开维护。
- 生成物：`build/` 可再生成，`plugins/` 放本机 DLL；`dist/` 只保留明确交付的当前成品。
