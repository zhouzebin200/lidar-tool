# 项目结构与维护

本项目只有一个面向检测人员的桌面入口：`run.py`（源码）或 `砺见智行工作室激光雷达测试工具.exe`（Windows 打包版）。点云查看器和检测报告由同一个本地 HTTP 服务提供，默认地址为 `http://127.0.0.1:17777`。先安全退出旧进程，再启动新 EXE；端口已由旧进程占用时，新程序可能只会打开旧页面，因此不能仅凭窗口外观判断升级成功。

## 主要目录

| 路径 | 用途 |
| --- | --- |
| `ulv/` | 服务入口、二层抓包、设备识别、PTC/网页读取、网络临时配置与恢复、PCAP 回放和原生插件管理。 |
| `web/` | 点云查看器、网关页面、报告编辑器、三视图桥接和 PDF/PNG 导出。 |
| `native/` | C ABI 与各厂家解码适配器源码。 |
| `plugins/` | 本机编译的原生解码 DLL；打包时嵌入 EXE。 |
| `corrections/` | 解码所需的标称修正文件；逐台工厂修正优先。 |
| `tests/` | Python 回归测试；`report_integration_harness.py` 用于报告集成检查。 |
| `packaging/` | Windows 融合版、历史授权版和 OpenWrt 网关的独立构建入口。 |
| `scripts/` | SDK 获取、原生插件编译与 PCAP 验证工具。 |
| `openwrt/` | 可选网关包，与 Windows 查看器分开部署。 |
| `build/`、`dist/` | 生成物和历史发布包，不是源码；以本次明确交付的版本为准。 |

`third_party/` 为 SDK 源码或依赖，`config/` 为本机运行配置，`tmp/` 为开发调试文件。不要把 `licensing/private/`、许可证私钥、`config/` 中的本机状态或整个项目目录发给最终用户。

## 数据进入报告的路径

1. `ulv/capture.py` 接收在线 UDP/PCAP 数据，`ulv/detection.py` 识别型号，`ulv/native_plugins.py` 调用厂家解码插件。
2. `ulv/registry.py` 保存当前设备；查看器的 `/api/devices` 和 `/api/status` 提供 IP、点云及插件状态。
3. 报告在 `web/report-viewer-link.js` 选择在线设备，再由 `web/report.js` 调用 `/api/lidar-web?ip=...`。
4. `ulv/lidar_web_scraper.py` 优先读取设备 HTTP/CGI 网页；网页不可达时才尝试兼容型号的 PTC。Pandar40P 的网页 `device_info`、`lidar_config`、`ethernet_all`、`TimeStatistic` 可提供型号、SN、生产日期、版本、转速、网络和运行统计。`ulv/hesai_ptc.py` 的 AT128 布局不得用于 Pandar40 系列的报告字段。
5. `web/viewer-report-bridge.js` 与 `web/report-viewer-link.js` 从当前点云帧生成斜视及两个侧视；`web/report-export.js` 负责报告 PDF/PNG 输出。

网页或 PTC 没有返回的电压、电流等值保持空白。软件队列丢包统计不能当作单台雷达的网络丢包率，点云帧率也不能当作机械转速。

## 开发、验证和发布

```powershell
./start.ps1
python -m unittest discover -s tests
python packaging/build_report.py
```

融合版构建脚本把 `web/`、`corrections/` 和现有 `plugins/*.dll` 一起嵌入 EXE。发布前检查 DLL 是否为新构建，并使用 `python packaging/audit_public_release.py <待发布目录>` 检查公开目录。`packaging/build_portable.py` 会生成历史普通版、授权版和私有发码工具；仅在确实需要该流程时使用，尤其不要公开私有发码工具。

更新后先正常退出旧程序，确保端口 17777 已释放，再启动新 EXE。进入报告读取同一台在线雷达，核对型号、SN、转速和运行时间，然后抽查 PDF/PNG。若 `/api/lidar-web` 返回 404，说明实际运行的仍是缺少该接口的旧程序。
